## 八、dup=117 是什么

`build_site.py` 报 `dup=117`，指 **t01 内有 117 个题号存在多份 article**，分布在 5 段：

| 题号段 | 题数 | 涉及文件 |
|---|---:|---|
| 4–6 | 3 | `seg-590-591` / `seg-590-597` |
| 254–264 | 11 | `seg-645-654` / `seg-646-647` |
| 501–530 | 30 | `seg-705-705` / `seg-705-709-v2` / `seg-708-709` / `seg-706-707` |
| 1338–1360 | 23 | `seg-839-848` / `seg-847-853` / `seg-848-856` |
| 1901–1950 | 50 | `seg-955-959` / `seg-955-964` / `seg-960-964` |

3+11+30+23+50 = 117。这是**页段重叠造成的真副本**（早期按页切片时有交叉），不是同名假卡。

站点加载规则是「同目录内按文件名升序，**article 更长者胜**，等长取先出现的文件」，所以读者不会看到错版；但**维护时改错份等于白改**——501–530 那 30 题曾因此整段逐字同步过一遍。收尾的多副本段动作是：定稿后把整块 article 逐字写入所有同号旧件，并逐题 sha1 校验。

## 九、记账口径的四个坑（这轮实测）

台账判定记的是**书的质量**，不是我们干了什么。四条口径：

- 书答错 → `fixed/answer`（答案栏改复算值 + 校勘块）；
- 书答对、但书印解析/分步有错 → `fixed/sol`；
- 书答对、解析也对，我们只是加厚/压薄/改措辞 → **`pass`**，改动记 note 的「治理：」段；
- 书没错、错在我们自己的卡（如变式 var-ans 写错）→ **`pass`** + 自纠记录。

据此，账实不符有**四类**，本稿实测计数如下（2850 张范围内）：

| 类型 | 张数 | 判据 |
|---|---:|---|
| ① 记 `fixed` 却无校勘块 | **70**（t01 64 + t02 6） | 多数是自纠（排版控制符修复、变式答案栏改正、sol 数值改写）被误记 fixed，应回 `pass` |
| ② 带校勘块却记 `pass` | **77** | 书答错且已校勘，应转 `fixed/answer` |
| ③ 带校勘块却记 `skip` | **18** | 用户点名的第四类；内容是好的、台账判错档，应转 `fixed` |
| ④ 变式答案栏自误被记 `fixed` | 计入 ① 的 70 张之内 | 主答与书值一致，错在我们自己的 var-ans |

净效果：台账 `fixed 494` 里 70 张不是书错；而 476（t01）+43（t02）张带块卡里，有 95 张（77 pass + 18 skip）没进 fixed。两边一通，**书答错的真实张数是 519（18.21%）**，台账口径 17.52% 偏低约 0.7 个百分点。上一版稿子里的「476 张 / 17.96%」就是把 t01 的带块数当成了全册书错率——数没错，口径停在 2650，且与台账 fixed 混用。

**这三类错记（①②③）尚未归位**，本稿只记不改（`checks.csv` 正由另一条线写入，避免撞锁）。

## 十、怎么核验（你发现问题时只说这一句）

> 「核验极限第 A–B 题」

执行顺序：页面图逐字对题干 → 独立复算（先算完再看卡片，避免被原结论带跑）→ 答案栏与校勘块一致性 → 变式 var-ans 与自身解析末步对拍 → 写台账 → 判 fail 即刻下线 → 修好重新发布。

已建立的判据：

- 判「书题面与答案矛盾」前**必须放大 ≥8–10 倍**并找同页字形标尺；分辨不了按书答并记「字形存疑」。150dpi 上 3 与斜体 n 极难分辨，已因此误判两次（2276、2364）。
- 判杜撰**必须亮页面图证据**（曾误撤 50 张真卡）。
- 书题面自身残缺 → `skip`，写「按原书印出的题面：±∞（原书疑漏印一项）」，紧跟校勘块说明书给值对应哪道题，**不许补全题面**。
- **「阶数不够」型题面**（如只给五阶可导却求 x⁶ 系数）：要么在题面补阶可导条件，要么按「条件不足」判——1731–1800 段已出现同一坑两种处置（q1795 判 fixed，q1775 维持 pass 并写明依赖约定），需统一。

## 十一、篇幅达标现状（不粉饰）

按现行三条硬线（sol 301–420、整卡 ≥620、行间公式 ≥3）全库实测：

| 指标 | 不达标张数 |
|---|---:|
| 三条全过 | **2131 / 2850** |
| 行间公式 <3 | **614** |
| sol > 420 | 122 |
| sol < 301 | 73 |
| 整卡 < 620 | 116 |

也就是说现有 2850 张里有 719 张至少缺一条。治理批（如 1731–1800 的 70 张）已全部拉进线，但早期批次只按「篇幅区间」验收、没补公式，所以公式缺口（614 张）是最大的一块，且会被「篇幅达标」这个结论掩盖——这是把「公式 ≥3」写进硬线的原因。

## 十二、怎么续做

| 目标 | 规模 | 估算 |
|---|---|---|
| 薄解析卡全部加厚 + 补公式 | 719 张里按段分批，每批约 50 张 | 单批约 1 小时 / 约 90 额度 |
| 四类记账错归位（①②③） | 70 + 77 + 18 = 165 行台账 | 半天内可完成，需与写 checks.csv 的线错峰 |
| 其余 15 册逐题精解 | 约 6.3 万题 | 按 0.25 额度/卡，约 1.6 万额度 |

开工话术：

- **「继续加厚薄卡并补行间公式，下一批 X–Y」**
- **「把 70/77/18 三类记账错按段归位」**
- **「开下一册，先做前 50 题样板」**

额度实测：约 0.25 额度/卡（含生产 + 校对）；单条线约 90 额度/小时。
