# 台账规范（LEDGER）

台账记录「每一题我们判成什么、为什么」。它是站点能否上线、返工清单从哪来、
书错率统计的依据。**它不是日志，是账。**

| 文件 | 覆盖 | 行数 |
|---|---|---|
| `work/checks.csv` | 第一册《极限》q1–q2650 | 2650 |
| `work/state/ledger-nxh-*.csv` | 第二册专题《n 项和极限》Q1–200 | 200（分 4 段） |
| `work/state/ledger-t01-*.csv` | 各段复核原始台账（留档，只读） | — |

**现状：第二册 200 张未并入 `checks.csv`。** 所以 `gate.py`、`spotcheck.py` 的统计只覆盖第一册；
做全库审计前先合并（合并前必须先清 `ledger-nxh-1-100.csv` 的 3 行串号，见 §9）。

## 2. 字段

```csv
q,page,verdict,note,time
1,590,pass,题干与图逐字一致(A/B/C/D 同书)；取 eps=|a|/2…,2026-11-18 12:39
```

- `q`：题号（整数，全库唯一）
- `page`：页面图编号（纯数字，如 590 对应 p00590.png）
- `verdict`：`pass` / `fixed` / `skip` / `fail` 之一
- `note`：一句话说清判据。**必须能让第二个人复核**，写清「书给什么、复算什么、为什么」
- `time`：判定时间

## 3. 四态定义（这是全项目最容易出错的地方）

| verdict | 含义 | 是否要有 caveat 块 |
|---|---|---|
| `pass` | 书答正确，卡也正确 | **否** |
| `fixed` | 书答（或书印解析）错误，卡已改正 | **是（必须）** |
| `skip` | 题面不可用（缺项不可辨 / `Tex translation failed`） | **否（必须没有）** |
| `fail` | 复核发现卡有硬缺陷，待返修 | 否 |

核心断言：**`fixed ⇔ caveat`**，两向都成立。

### 判定矩阵

| | 书答对 | 书答错 |
|---|---|---|
| **卡正确** | `pass`（只加厚/压薄/补公式 → note 写「治理：…」） | `fixed/answer`（答案栏=复算值 + caveat） |
| **书答对、书印解析错** | `fixed/sol`（保留 caveat，写「书印解析在……一步错，结论仍对」） | — |
| **卡有错** | `pass` + note 写自纠记录（**不能记 fixed**） | 先修卡，再按上面判 |

`skip` 不参与上表：它只看题面能不能读出来。

## 4. 口径演进（三版，别退回旧版）

1. **v1**：`verdict` 只看「书答对不对」。结果加厚、压薄、补公式都被记成 `fixed`，fixed 虚高。
2. **v2**：细分 `fixed/answer` 与 `fixed/sol`；加厚/压薄改记 `pass` + note「治理：」；卡自身有错也记 `pass` + 自纠记录。
3. **v3（现行）**：`skip` 只留给题面不可用；确立 `fixed ⇔ caveat` 为唯一账实判据。

## 5. 两个写账工具（不要手改 csv）

### `merge_ledger.py` —— 新段首次入账

```bash
python3 work/merge_ledger.py work/state/ledger-t01-1621-1730.csv
```

- 全流程持 `flock`，禁并发写。
- 同题号冲突时按 **`fixed < pass < skip < fail`** 取（fail 优先，宁可下线不漏错）。
- 只增改不删。

### `rerecord.py` —— 改判（pass↔fixed↔skip）

```bash
python3 work/verify/rerecord.py work/state/ledger-xxx.csv
```

- **强制覆盖**同题号行，带 flock。
- 只接受 `pass / fixed / skip`；`fail` 会被跳过并提示「仍需返修」。
- **只要 verdict 变了就必须走它**，因为 `merge_ledger` 的排名规则无法把 fail 降回 pass，也无法把 pass 升成 fixed 之外的语义。

两条都先 `cp` 备份 `checks.csv`。

## 6. 四类账实不符（当前 105 张待清）

```bash
python3 work/qa/ledger_audit.py          # 全库
python3 work/qa/ledger_audit.py 1401 1500
```

| 类型 | 当前 | 含义 | 处置 |
|---|---:|---|---|
| 记 fixed 却无 caveat | **64** | 多为纯变式修正 / 排版修复误记成书错 | 复核后降 `pass`，note 写「自纠/治理」 |
| 带 caveat 却记 pass | **41** | 书答确实错、卡也给了复算值，但没升档 | 回图确认后升 `fixed` |
| 带 caveat 却记 skip | **0** | 卡对、判档错 | 已清（16 转 fixed、2 删块保 skip） |
| 变式自误被记 fixed | 计入第一类 | 变式 var-ans 与自身解析不一致，被当成书错 | 改 var-ans，回退 pass |

**第一类要小心**：不是所有「fixed 无块」都是记错。判据是看 note 与卡片内容——
如果答案栏确实是复算值、而书值无处记录，那才是缺块（应补块或降 pass）。

## 7. 统计口径（两套数并存，别混用）

| 口径 | 全册值 | 含义 |
|---|---:|---|
| 台账口径 `fixed / (pass+fixed)` | **17.52%** | 以台账判定为准；含 70 张「fixed 无块」的虚高部分 |
| 带 block 口径 `caveat 数 / 卡片数` | **18.21%** | 以实际写出的校勘块为准，更接近「书答真错率」 |

交叉表：`work/state/cross-table-2850.csv`（100 题一组）。
分半：1–1200 → 13.6%；**1201–2850 → 20.4%**。最高段 1801–1900 = 64.0%，最低 801–900 = 1.0%。

`交付说明.md` 里旧稿的「476 张 / 17.96%」是第一册 2650 口径的带块数，**不能当全册书错率用**。

## 8. 记 note 的三条要求

1. **写判据，不写结论**：「书给 1/6、实为 1/9（漏乘权重 1/n）」优于「答案错」。
2. **写清复算依据**：用了哪种方法（mpmath 高精度、黎曼和双验、三档取值外推）。
3. **区分「书错」与「卡错」**：卡错写「自纠：…」，别写成「书给…」——它会诱导后面的人去找一个不存在的书错。
